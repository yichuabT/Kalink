Computer Network Protocols.

Protocols are a set of rules that govern data communication.
It determines: what is communicated, how it is communicated, and when it is communicated in the network.
Now let's see some very common Network Protocols one by one.

DHCP(Dynamic Host Configuration Protocol).

The main job of this protocol is giving an IP address automatically to our devices when they connect to a network.

Why we need DHCP?
So without DHCP we should give IP address to all our devices manually (by typing). this is normal for small network or just for home network, but what if you are a Network Admin in very large company? manually typing IP address to all devices is samsthing unthinkable right? so this is why exactly we need DHCP. because as we said before it can assign IP address to all devices connected to the network automatically.

DNS(Domain Name System).

What do you think happening when you type www.Google.com on your browser?
basically computer did not understand the domain name you are looking for. so there should be something that can translate what you typed on your browser to what computer actually understand, that protocol is DNS.

DNS finds the IP address of www.google.com so that your browser can access Google's server. When you type some website's name on your browser, your computer sends a DNS query to DNS server through port 53. and the server read the domain name and translate it to IP number and send back to your browser so your browser uses that IP to connect.

HTTP(Hypertext Transfer Protocol).

This is how our browser request web pages to servers. when we type URL then HTTP request over port 80 to server, then the server will send back HTML files to our browser.
Early days, everyone should see http:// in the address bar when they visit website. but these days almost every websites moved away from HTTP.
The reason is http sends everything in plain text (no encryption). Notice that No Encryption is no security. so here is HTTPS comes to play.

HTTPS(Hypertext Transfer Protocol Secure).

It does almost exactly what HTTP does, but it adds encryption. It uses port 443 so anytime you visited a website through HTTPS all your communication between your browser and the server is encrypted.

TCP(Transmission Control Protocol).

TCP ensures data is delivered completely and in the right order. It works at the lower level of HTTP or HTTPS. it is the delivery method under those protocols.
TCP protocol is based on three way handshake. there are three steps called:
1. SYN: stands for synchronize sequence number. simply the client computer sending request for connection.
2. SYN/ACK: the server acknowledging the request.
3. ACK: the client responds the acknowledge to the server.(connection is established)

When you download file, TCP breaks that data into packet and send them and confirms all are arrived. if one of them gets lost TCP automatically resends it.
It is a connection first protocol.
For live video or Gaming where speed matters more than reliablity, TCP is slower because of all error checking and confirmation. every packets needs acknowledgment. then here is UDP comes to play.

UDP(User Datagram Protocol).

This protocol is the opposite of TCP.
It doesn't establish a connection, it doesn't confirm delivery.
Unlike TCP if the data packet gets lost it doesn't care. so this is what makes UDP faster than TCP. for anything realtime UDP is the best.
If you are transferring important files or needs guarantee delivery UDP is the wrong choice.

SMTP(Simple Mail Transfer Protocol).

It is specifically for outgoing email.
It is the postal service of the internet moving messages from sender to receiver. it uses port 25 for server to server communication or port 587 for sending our email client, port 465 is used for secure SMTP with encryption.
SMTP handles sending and IMAP & POP3 handles receiving.

FTP(File Transfer Protocol)

It is specifically designed for moving files. it uses two ports : port 21 for commands and control, port 20 for the actual data transfer.
Note that, FTP sends everything in plaintext (usernames, passwords...) or no Encryption by default this is why SFTP AND FTPS exist. but regular FTP is used widely.
